# Contributing

Issues and PRs are **disabled** — the project is agent-maintained.
Fork freely under MIT.

## Layout

`crates/` — flat rust workspace. `cypera-core` is pure domain
(models + markdown renderers, **no I/O** — `std::fs`/`std::process`
never appear there). `cypera` (package in `crates/cypera-cli`) is
the composition root: clap argv, filesystem walks, emit. `xtask`
is workspace automation (`cargo xtask check|test|coverage|fmt`).

## Rules of thumb

- New generator = a `cypera-core` model + renderer plus a `gen`
  subcommand — keep the core pure.
- `cargo xtask check` (fmt + clippy `-D warnings`) and
  `cargo xtask test` must stay green. Warnings are errors.
- Coverage: `scripts/coverage.sh` — cargo-llvm-cov HTML report in
  `target/llvm-cov/html`; pass `--fail-under-lines 100` to gate.
- Keep the binary dependency-light and sync; no async runtime.
- Commits: conventional prefixes (`feat:`/`fix:`/`refactor:`/`docs:`/`chore:`).
- Never commit secrets — config files take names, not values.

## Docs

Follow Diátaxis on the `docs` branch: `docs/tutorials/` (learn) ·
`docs/how-to/` (tasks) · `docs/reference/` (lookup) ·
`docs/explanation/` (why). The branch mounts as the `docs/` worktree.

Dogfooding: cypera's own reference pages are generated by cypera —
`cypera gen crate-map --repo . --out docs/reference/crate-map.md`.

## Releasing

`scripts/release.sh` is run manually by an operator on `main`
(releases are operator-run) — a thin shim over `tarsi-serve
release` (plan → changelog → bump → tag → push; publish targets
off per ADR-0004).
