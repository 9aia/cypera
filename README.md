# cypera

Reusable documentation/reference generation for the 9aia org — the
shared successor to the per-repo `docs/gen-*.py` scripts.

Named for *Cypera*, the swift — docs that keep pace with the code.

Every sibling repo's VitePress site regenerates the same three pages
from the same sources: a **crate map** (workspace `Cargo.toml`s +
`lib.rs` module docs), a **CLI reference** (each engine's
`gen-cli-docs` verb — clap-markdown output), and a **config
reference** (config-struct doc comments). cypera renders all three,
once, for every repo — killing the per-repo script drift.

## Install

The `cypera` command ships as a [tamias](https://github.com/9aia/tamias)
pack (`libraries/cypera`) — a generated `bins[]` shim over
`tamias-driver-cypera`, like every other 9aia tool. With `tamias`
installed:

```bash
tamias install --allow-drivers ./libraries/cypera   # from a checkout (after cargo xtask pack)
```

From a checkout without tamias:

```bash
cargo install --path crates/cypera-cli   # or: cargo build --release -p cypera
```

Requires a Rust toolchain (stable); no other runtime deps.

## Usage

Every generator accepts `--out`; without it, markdown goes to stdout.

### `cypera.toml` — the per-repo contract

Drop a `cypera.toml` at the repo root (discovered upward from
`--repo`/cwd). It declares everything the per-repo `gen-*.py`
wrappers used to hard-code:

```toml
[crate_map]                          # gen crate-map
out = "docs/reference/crate-map.md"  #   full-page emit target
order = ["domain", "port", ...]      #   optional layer ordering
"default_layer" = "impl"             #   optional fallback layer
[crate_map.layers]                   #   per-crate layer overrides
"my-crate-xtask" = "tooling"
[[crate_map.splices]]                #   in-place table splices
file = "docs/explanation/architecture.md"
marker = "<!-- crate-map -->"        #   or first_table = true
[crate_map.crate_api]
site = "myrepo"                      #   → reference/crate-api.md
out  = "docs/reference/crate-api.md"

[cli]                                # gen cli — recursive --help walk
package = "my-engine"                #   cargo package to build
bin     = "my-engine"                #   name under target/debug/, or a
                                     #   direct executable path (no package)
prefix  = ["my-engine"]              #   argv prefix before subcommands
title   = "Command-Line Help for `my-engine`"
out     = "docs/reference/commands.md"  #   freshness target for `check`

[config]                             # gen config — curated pages
out = "docs/reference/config.md"
structs = ["AppConfig", "ServerConfig"]
files   = ["crates/x-core/src/config.rs"]
title   = "Config — myrepo.toml"
[config.types]                       #   Rust type → display name
"std::collections::HashMap" = "map"
[config.field_types]                 #   struct.field → display name
"AppConfig.repos" = "list<repo>"
[[config.sections]]                  #   table + optional prose
struct = "AppConfig"
title  = "### `AppConfig`"
prose  = "Shared across every section."
[[config.sections]]
title  = "## Notes"
prose_file = "docs/snippets/notes.md"
[config.style]                       #   marker / table-head overrides
marker = "<!-- generated by gen-config-docs.py -->"

[api]                                # gen api — rustdoc site (all optional)
out        = "docs/public/api"       #   target/doc copy destination
prefix     = "myrepo"                #   index filter + title base
target_dir = "target/docs-api"       #   CARGO_TARGET_DIR when unset
```

With the file present, the generators need no flags:

```bash
cypera gen crate-map --repo ../myco   # writes every declared target
cypera gen cli       --repo ../myco
cypera gen config    --repo ../myco
cypera gen api       --repo ../myco   # cargo doc → docs/public/api
```

The legacy explicit-input modes still work (`--file` for config,
`--input` stdin/file wrapping for cli, `--layer`/`--out` overrides
for crate-map) for repos not yet migrated.

### `cypera check` — the docs contract

```bash
cypera check --repo ../myco           # text report, exit 1 on FAIL
cypera check --repo ../myco --json    # machine-readable
```

Rules: README shape (what/why/quickstart, <200 lines, install/run
command), `AGENTS.md` sections (Layout/Commands/Boundary), no
`CHANGELOG.md`, no version numbers in prose (manifests/lockfiles,
fenced code blocks, inline code spans, and `<script>`/`<style>`
HTML blocks exempt — doc comments count), Diátaxis `docs/`
layout, `docs:check` script in `docs/package.json`, and
generated-file freshness — cypera regenerates every output
declared in `cypera.toml` in-memory and diffs (no writes).

Repos where a rule doesn't apply by design exempt it via
`[check] skip = ["docs-site", ...]` in `cypera.toml` — the rule
still runs but reports `SKIP` (unknown names warn, never fail).

## Layout

| Crate | Role |
| --- | --- |
| `cypera-core` | Pure domain — manifest models, doc-comment scanners, markdown renderers. No I/O. |
| `cypera` (`crates/cypera-cli`) | The `cypera` binary — clap front-end, filesystem walks, stdout/file emit. |
| `cypera-xtask` | `cargo xtask check/test/coverage/fmt` workspace automation. |

## Docs

The `docs/` worktree (orphan `docs` branch) holds the VitePress +
Diátaxis site → GitHub Pages at `9aia.com/cypera`. Build with
`bun run docs:build` from `docs/`.

## Releasing

`scripts/release.sh` is an operator-run shim over `tarsi-serve
release` (tag-only; see `tarsi.toml`).
