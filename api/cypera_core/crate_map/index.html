Module crate_map 

Source
Expand description

Crate-map model + markdown renderer — the reusable successor to the per-repo docs/gen-crate-map.py scripts.

Input is already-decoded WorkspaceManifest/CrateManifest values plus optional entry-file scans (EntryScan); output is a markdown page. No I/O.

The whole crate map for a repo.
EntryScan
A crate’s entry file (src/lib.rs or src/main.rs) scan — module declarations and the //! crate doc, extracted by the IO layer.

Constants§

DEFAULT_LAYER_ORDER
The canonical layer order — reproduces the relative ordering every per-repo gen-crate-map.py ORDER table agreed on. cypera.toml [crate_map].order replaces it wholesale when set.

crate_api_page
The rustdoc link-list page — one - [crate](/<site>/api/<crate>/index.html) — <layer> per crate, the reference/crate-api.md the per-repo gen-crate-map.py wrappers emitted as a second output.
crate_map_from_workspace
Build a CrateMap from a parsed workspace manifest and the per-member crate manifests. members pairs each declared member path with its parsed manifest; entries optionally pairs member path → EntryScan. order is the [crate_map].order layer ranking (empty = DEFAULT_LAYER_ORDER); default_layer replaces the "adapter" guess fallback (None = "adapter").
crate_map_table
The bare | crate | layer | purpose | table — used both by render_crate_map and by --out marker splicing (the <!-- crate-map --> convention the per-repo python scripts used inside explanation/architecture.md).
guess_layer
Conventional layer guess from the crate name — the port-and- adapter naming convention (<repo>-core is domain, -cli the binary, bare <repo> the composition root, everything else an adapter/port). Callers may override per crate; the unclassified fallback is "adapter" — see guess_layer_as for the cypera.toml [crate_map].default_layer knob.
guess_layer_as
guess_layer with a configurable unclassified fallback — the kuda/mimus "impl" convention.
purpose_from_entry_doc
Collapse an entry-file //! doc block into a one-line table-cell purpose — the tidy() half of the per-repo gen-crate-map.py description() fallback: drop code fences, unwrap [text](url) links, [code] → `code`, collapse whitespace, cap at ~200 chars on a sentence boundary.
render_crate_map
Render the crate map as a markdown page: summary table, then a per-crate section with the lib.rs doc and module list when an EntryScan was supplied.
scan_entry_source
Scan an entry-file source (src/lib.rs or src/main.rs) for the crate map’s detail section: leading //! inner doc lines and top-level mod/pub mod declarations. Pure string scanning — mod foo { … } inline blocks and #[path] attributes are not resolved (the module name is still listed).
splice_first_table
Splice table over the first | crate | … table in existing — the bupha/kuda/mimus wrapper convention (their architecture pages carry no marker). Returns the input unchanged when no crate table exists (the wrappers’ no-op).
splice_marked
Splice table into existing after the first line containing marker: the run of |…| lines following the marker is replaced (the <!-- crate-map --> convention). None when the marker is absent.
