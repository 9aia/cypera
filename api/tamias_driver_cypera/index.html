tamias-driver-cypera — the pavo driver for a cypera workspace, plus the engine ops surface.

Verbs (the tamias driver contract):

  • manifest — print the [DriverManifest] JSON (discovery probe; never touches workspace state).
  • capabilities — {"capabilities": ["pavo"], "verbs": […]}.
  • ops — the engine ops manifest: every bounded cypera CLI verb as a cli.<verb> wire query, derived from the engine’s own clap tree (cypera::command). Unbounded/host-interactive verbs are surfaces, never ops (cypera has none today).
  • run <argv> — engine passthrough: tamias-driver-cypera run check ≡ cypera check. Also the child side of cli.* wire queries (ops::run_verb re-execs this same verb so engine output never touches the serve stream).
  • cli <cypera argv> — the tamias bins[] shim verb: tamias bin exec calls it with the standard --dir/--name driver flags ahead of the user’s argv; they’re stripped and the rest runs through cypera::run_from in-process with inherited stdio — full engine parity (--help/version, globals, --json, stdin-bound flags all work).
  • serve — ndjson JSON-RPC on stdio: {"op":"manifest"}, {"op":"views"}, {"op":"view","view":…,"params":{…}}, {"op":"query","query":…,"params":{…}} → {"ok":true,"result":…} / {"ok":false,"error":…}. query:"ops" answers the ops manifest; query:"cli.<verb>" runs the engine op.

Optional surface: feature mcp embeds pavo-driver-kit’s surface layer — mcp serves the ops manifest as MCP tools on stdio, equivalent to the standalone tamias-driver-mcp surface driver minus the PATH/discovery hop. (cli needs no feature: it’s the bins-shim passthrough above, not a generated surface — the engine’s own argv grammar is the contract.)

Which repo: ops inherit the serve process’s cwd — each verb’s --repo/--config params map straight onto the engine’s own flags, and absent them cypera’s upward cypera.toml discovery applies, identical to running the cypera verb by hand. This driver ships no views — it is the engine-ops surface for cypera workspaces; view/query names outside ops/cli.* answer ok:false.

Modules§

ops 🔒
Engine ops — cli.<verb> wire queries dispatch into the cypera engine lib through this binary’s own run verb: each call re-execs tamias-driver-cypera run <argv> with the request’s params mapped to cypera’s flags, so cypera::run writes to the child’s captured stdout and never touches the serve loop’s ndjson stream — and every mutation keeps the engine’s own semantics (repo resolution, cypera.toml discovery, checks).
