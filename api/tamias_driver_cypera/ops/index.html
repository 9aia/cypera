Module ops 

Source
Expand description

Engine ops — cli.<verb> wire queries dispatch into the cypera engine lib through this binary’s own run verb: each call re-execs tamias-driver-cypera run <argv> with the request’s params mapped to cypera’s flags, so cypera::run writes to the child’s captured stdout and never touches the serve loop’s ndjson stream — and every mutation keeps the engine’s own semantics (repo resolution, cypera.toml discovery, checks).

ops answers the ops manifest as JSON — derived from the engine’s own clap tree (cypera::command), so a verb can’t exist on the CLI and be missing here: declared args become typed params (arg/opt/flag), doc strings ride along unchanged.

cypera has no unbounded or host-interactive verbs today — every gen/check call is bounded and stdin-free, so surfaces is empty. The classification stays: a future verb that never returns or needs inherited stdio/tty joins SURFACES and rides run passthrough / generated-surface subcommands instead.

mutates is honest: gen.* verbs write via --out (and gen cli’s help-walk mode runs cargo build, writing target/), so they count as mutating; check only reads. Streaming flags would join SKIP_PARAMS — none exist today.

Constants§

READ_ONLY 🔒
Read-only verbs — everything else writes files (--out, cargo build artifacts). Mutators belong behind a deliberate trigger, not ambient view polling.
SKIP_PARAMS 🔒
Params excluded from ops — flags that turn a bounded verb into a stream, or params that must never ride argv. None today.
SURFACES 🔒
Unbounded/host-interactive surfaces — verbs that never return or need inherited stdio/tty. They can never be request/response ops. Empty today: every cypera verb is bounded.

Functions§

argv 🔒
cli.<verb> params → cypera argv (no argv[0] — run prepends it). Declared params map by kind — positionals land last, in schema order; repeatable opts (--layer, --file, --only, --prefix) flatten array values into repeated flags.
kind 🔒
A clap arg → the manifest’s typed param kind — arg = positional, opt = --name <v>, flag = --name — the contract pavo-driver-kit’s surface layer renders args from.
manifest
The ops query/ops argv verb payload — self-describing so hosts and agents discover the engine surface without argv help. cypera has no globals — --repo/--config are declared per-verb and ride the normal param mapping.
op_cmd 🔒
op_of
Is query an engine op (cli.<verb>)? Returns the verb name.
param_json 🔒
run_verb
Run one engine op by name: re-exec run in a child with captured output, and hand back {op, argv, code, stdout, stderr} as the query payload. ok:false is reserved for spawn failures — a nonzero code is the engine’s own exit status (e.g. check findings), honest data. The child’s stdin is null and it inherits this process’s cwd — --repo/--config params (or upward cypera.toml discovery) pick the target repo.
scalar 🔒
A wire scalar → its argv token (numbers/bools stringify).
skipped 🔒
Args that can’t ride the wire: streaming flags (above) and clap’s own help/version actions.
values 🔒
All values of a param — arrays flatten, scalars wrap.
verbs 🔒
(name, clap spec) for every leaf verb. Hidden plumbing and clap’s help are skipped — they stay reachable through run passthrough.
