# Regenerate the CLI reference

Sibling engines expose a `gen-cli-docs` verb that prints their clap
tree as markdown (via `clap-markdown`). cypera wraps that output in
a reference page — it does not parse clap itself.

## Pipe it

```bash
myco gen-cli-docs | cypera gen cli \
  --title "myco — commands" \
  --out docs/reference/commands.md
```

From a file instead of stdin:

```bash
myco gen-cli-docs > /tmp/myco-cli.md
cypera gen cli --input /tmp/myco-cli.md --title "myco — commands" \
  --out docs/reference/commands.md
```

`--input` defaults to `-` (stdin); `--title` defaults to `Commands`.

## What the page looks like

```markdown
# myco — commands

<!-- generated by cypera gen cli — regenerate, don't hand-edit -->

<the gen-cli-docs markdown, verbatim>
```

The body is passed through untouched — command-tree formatting is
the producer's job (`clap-markdown` today); cypera owns only the
page chrome and the "regenerate, don't hand-edit" marker.

## Adopting in a repo without `gen-cli-docs`

Add the verb to the engine (see `myco-cli`'s
`clap_markdown::help_markdown_command(&command())` for the two-line
shape), then wire the same pipe into the docs worktree's regen
script.
